# AGENTS.md

## Commands
- `make verify` is the canonical repository-wide gate; it runs build, test, lint, verify-no-deps, and build-targets. `make build-targets` cross-builds and vets all four GoReleaser targets (darwin and linux on amd64 and arm64).
- `make build` builds `bin/tao` from `./cmd/tao`.
- `make test` runs `go test -coverprofile=coverage.out ./...` and prints coverage with `go tool cover -func`.
- `make update-golden` regenerates the golden fixtures under `internal/cli/testdata` by running tests matching `Golden` with `-update`; it is scoped to `./internal/cli` because the flag is defined only there, and it is never part of `make verify`.
- Run focused tests with `go test ./internal/<package> -run TestName` for ordinary implementation slices; examples: `go test ./internal/plan -run TestFormatDuration`, `go test ./internal/cli -run TestRunHandlesNoArgsAndGlobalFlagErrors`.
- `make install` copies `./bin/tao` to `~/.bin/tao`; do not assume this path exists.

## Shape
- [docs/agent-input-trust.md](docs/agent-input-trust.md) is the maintainer audit of agent-written inputs and their mitigations.
- This is a Go module (`github.com/iamseth/tao`) targeting Go `1.26.2` in `go.mod`.
- CLI entrypoint is `cmd/tao/main.go`; command parsing lives in `internal/cli`.
- Shared monitor row label projection and status roles live in `internal/monitor/rowlabel`; TTY/color detection lives in `internal/term`, and the shared palette and themes live in `internal/theme`.
- Cross-process plan run locks live in `internal/plan`; the run header view model and renderer live in `internal/runheader`.
- Plan file loading, validation, summaries, and time formatting live in `internal/plan`.
- Read-only plan deltas and review-base resolution live in `internal/plandelta`; `internal/tui` owns Changes mirror types, with stateless mapping in `internal/cli`.
- Share-safe report projection, sanitization, and Markdown rendering live in `internal/planreport`; render only its explicit safe projection, never raw plan artifacts, and keep planning-only reports free of prompt capture and execution-derived data.
- Reusable run, lifecycle, workspace, and repository behavior belongs in domain packages; CLI handlers should remain thin orchestration layers.
- Sparse setting value types live in `internal/configtypes`; canonical setting schema, parsing, layered resolution, and operation-scoped admission live in `internal/runtimeconfig`. `internal/settings` owns global/repository storage and the shared CLI/TUI service; `internal/taodata` retains repository identity and compatibility adapters. Bootstrap path projection is read-only; settings never authorize lifecycle or recovery actions.
- Shared bounds for agent-written input files and text live in `internal/agentinput`; strict commit-proposal decoding lives in `internal/commit`; slice-completion evidence loading lives in `internal/run`; plan base-commit drift detection lives in `internal/staleness`; repository-selector resolution lives in `internal/taodata`.
- Repository-scoped note models, persistence, lifecycle, and promotion locking live in `internal/note`; bounded external-editor note buffers and sessions live in `internal/noteeditor`; platform clipboard helpers live in `internal/clipboard`; note command and TUI edit orchestration live in `internal/cli`.
- Checked-in CI uses `.github/workflows/ci.yml` to execute the gates in `make verify`, including `make build-targets` in the Linux build job, and `.github/workflows/release.yml` to build tagged releases; ci.yml uses a workflow-level concurrency group keyed on workflow name and ref to cancel superseded in-progress runs for non-main refs and never cancel main runs. The Linux lint job also runs `make lint-darwin` because native lint on macOS covers darwin, while Linux would otherwise never lint darwin-gated files; lint-darwin stays separate from lint and verify.

## Tao Plan Data
- Runtime commands accept `--plans-dir DIR`; otherwise current-repo plans under Tao data home (`TAO_DATA_HOME`, `$XDG_DATA_HOME/tao`, or `~/.local/share/tao`) are used.
- Plan directories contain `state.json`, `slices.json`, and optional `events.jsonl`; new `/tao-slice` plans also include `planning-brief.md` and should record `state.repo.base_commit` for `tao staleness` checks, while old plans without it stay readable with warning-only validation findings. Completed reviews are stored as `review.md` plus state/event metadata in the data-home plan dir only, never the worktree or branch. Invalid plan directories are surfaced as warning summaries instead of aborting list output.
- Plan and merge batch directories gain a `prompts/` directory of captured non-interactive session prompts; it is local-only and never read by plan loaders.
- `/tao-slice` writes core plan artifacts only; planning-session capture is no longer supported and new plans should not create planning-session sidecars.
- Notes belong to one registered repository and live only under that repository's data-home `notes/` directory. The current checkout is the default; `--repo` accepts a unique ID prefix or exact name. Legacy global note files are deliberately ignored.
- Notes are a CLI-only backlog: do not add note API routes, dashboard views, or web assets. `/tao-plan note:<id>` reads an open or legacy planning-promoted note as untrusted context; after `/tao-slice` creates and validates a same-repository normal plan, linked archival is locked, idempotent for that plan, and terminal. Historical planning-session provenance remains readable, while new planning-session records are not created. The unchanged `tao note run` path still serializes direct promotion to a validated normal plan without losing recovery information.
- `tao init` registers the current checkout; `tao repo list/show/doctor` inspect the centralized repo catalog and health without destructive repo changes. `tao config get/set/unset` manages scoped preferences (current registered repository by default; `--global` or `--repo ID` selectors). For one release, `tao repo config [--pull-request true|false|unset] [--model NAME|unset] [--run-model NAME|unset] [--review-model NAME|unset] [--merge-review-model NAME|unset] [--resolver-model NAME|unset] [--rework-escalation-model NAME|unset] [--effort NAME|unset] [--run-effort NAME|unset] [--review-effort NAME|unset] [--merge-review-effort NAME|unset] [--resolver-effort NAME|unset] [<repo-id>]` remains a compatibility adapter.
- IDs can be addressed by unique prefix in `tao show`; ambiguous prefixes are errors.
- Tao data-home contents and workspace-local `.tao/` metadata are local-only and must not be committed.
- Workspace cleanup is explicit and preview-first: `tao workspace clean <plan>` removes worktrees only after force flags, while `tao cleanup` classifies Tao-managed branches and worktrees from live Git merge state, including unreferenced integration namespaces (`tao/integration` branches and `.tao/integrations` worktrees), never the active merge batch. Integration cleanup resolves the control-repository identity from Git's common directory, not the linked checkout's top level; unresolved identity skips integration cleanup even with `--force`. Integration cleanup must hold the control repository's existing batch ownership lock before reading active state through enumeration and removal; lock contention (including a live dry run without active.json) skips integration cleanup even with `--force`, without blocking ordinary plan cleanup. Unregistered integration directories are report-only and never removed, even with `--force`. Keep protected, dirty, current, and unmerged safeguards. PR lifecycle completion alone never authorizes removal.

## Documentation Boundaries
- `README.md` is user-facing: keep it concise and focused on install, workflow, commands, and links.
- `docs/configuration.md` is the complete settings reference (every runtime env setting with default and purpose, budgets, model precedence, planner routing); README keeps only the common settings and links there, and the coverage test in `internal/runtimeconfig` must pass whenever a runtime env key is added.
- `AGENTS.md` is agent-facing: keep it focused on commands, repo shape, and rules that prevent bad edits.
- `docs/plan-format.md` is the concise contract for plan artifacts; avoid duplicating schema details elsewhere.
- `docs/usage-guide.md` is user-facing workflow judgment (when/how to use each command); keep command and schema reference in `README.md` and `docs/plan-format.md`, not there.
- Prefer package comments for ownership/invariants and avoid comments that restate obvious Go code.
- Tao is CLI-only while its workflows stabilize. A future web UI is deferred; keep new domain and lifecycle behavior reusable behind thin CLI handlers, and do not introduce a browser control plane or duplicate workflow implementation without explicit owner direction.

## Current Behavior To Preserve
- `run_aborted` is best-effort diagnostic journaling from the `tao run` lock boundary, classified only from typed errors, skipped for cannot-start refusals and lock contention, never lifecycle or recovery authority, and never read by plan loaders. Abort enrichment reuses entry metadata (possibly stale), never recovery-loads under the mutation lock, and gives optional HEAD lookup an independent 250ms timeout; diagnostic writes finish synchronously before releasing the run lock. `ui-launch.log` is a Tao-owned, local-only runtime operation file written by the dashboard launcher for detached run, approval, and single-merge stderr, truncated per launch, diagnostic only, and never read by loaders; `merge --all` keeps the null device.
- The control-checkout leak guard reports concrete paths, tracked state, and HEAD moves with neutral wording. Attribution is a run-side policy over Plan-Owned Files and slice `expected_files` plus execution-worktree cleanliness; unattributed changes journal `control_checkout_changed` (diagnostic only, never lifecycle, recovery, or merge authority). Sessions without an attribution callback stay fail-closed.
- Review `required_files` are untrusted; the rework scope gate is a runnable error lifted only by an `expected_files` amendment, and the rework fingerprint ignores `required_files`.
- The planner routing ledger under `repos/<repo-id>/planner-routes` is local, bounded, and non-authoritative: never lifecycle or recovery evidence, never copied into plan events or state, and never read by plan loaders.
- Resolve settings built-in → global → repository → environment → flags, retaining explicit `false`, `0`, absent/inherited, and STOP `null`/disabled distinctions. Capture environment once per invocation; preserve invalid saved-layer diagnostics even under valid environment masking. Global `config.json` uses `tao.config.v1`; repository `repo.json` retains `run_defaults` and legacy model/PR shape. CLI/TUI updates share serialized atomic persistence and preserve unrelated metadata. Theme/update are global-only; bootstrap paths, process/merge-only controls, and recovery actions are not persisted.
- Resolve model fields with the same scoped precedence, then let unset roles fall back to base; explicit invocation `--model` overrides base and roles. Never retry or fall back on runtime rejection, or treat model selection as lifecycle authority ([model rules](docs/usage-guide.md#choose-models-for-agent-sessions)).
- `tao validate` checks plan artifact consistency and verification commands; `tao run` preflights only the selected runnable slice ([validation](docs/plan-format.md#validation)).
- Only Tao-derived ownership and matching head/worktree fingerprints authorize unchanged-`plan_owned` blocker refusal; prose is not evidence ([events](docs/plan-format.md#events)). `gate_parity` is advisory, never execution authority ([validation](docs/plan-format.md#validation)).
- Completion requires merge evidence or approval plus matching non-empty PR head; only current `plan_merged` proves integration, while legacy completion stays readable ([lifecycle](docs/plan-format.md#state-lifecycle)). Review failures remain best-effort ([run workflow](docs/usage-guide.md#tao-run-and-tao-run--execute-slices)). A no-changes plan (every slice `no_changes` at the live tip, tip ancestral to default, approved review at that head) records `plan_merged` through the external-merge record path without a commit, intent, or `--force`, and an empty squash is `ErrNoChangesToIntegrate`, never a merge conflict.
- PR recovery requires exact approval, workspace, push, intent, and remote identity evidence; proposal/head checks precede mutation, and failure diagnostics never authorize recovery ([finalization evidence](docs/plan-format.md#state-lifecycle)).
- `slice` is the only automatic commit policy: the active agent proposes, Tao validates and alone persists intent/stages/commits; no nested message session or fallback. Recover only exact parent/message, including historical intents; `none` stays manual and `expected_files` advisory ([commit contract](docs/plan-format.md#slice-lifecycle)). Automatic staging is split by porcelain state: already staged entries are skipped, tracked changes are staged with `git add -f`, and untracked paths use plain `git add`; the merge fingerprint-less legacy path still stages `.` without force.
- Tao-owned gates run before intent; claims never authorize completion, and frozen-intent recovery never reruns gates. Preserve command/session bounds, cancellation, historical decoding, and Tao-only mechanical corrections; no skip switch ([observed verification](docs/plan-format.md#observed-slice-verification)).
- Automatic verification repair belongs in `internal/run` via `ExecutionConfig`, not `run.Request`; reload/re-derive after each journaled append; generated repair slices accept only appended expected_files, tasks, and manual_checks through `tao edit amend`; their goal, verification commands, and repair binding stay frozen. Under the cap, a code failure whose failing packages and diagnostic paths are all outside Plan-Owned Files is probed once at the resolved base in a temporary detached checkout and recorded as `baseline` (reverify, never automatic repair, never counted against the cap) only when the base run shares a failing test or package; every probe error keeps `code`. Preserve admission, the fixed lifetime cap of two, invocation slice budget, and explicit-only recovery for already-failed plans ([repair evidence](docs/plan-format.md#final-verification-repair-evidence), [workflow](docs/usage-guide.md#tao-run-and-tao-run--execute-slices)).
- `tao run` prompts should use the compact run packet first and read fallback plan artifacts only for a concrete reason such as missing, stale, blocked, or failure-diagnosis context.
- The run header is best-effort presentation, TTY-only, and never affects run outcomes.
- Changes shares review-base resolution, uses plan-recorded roots and pinned read-only Git options, and is presentation only: never approval, recovery, or merge authority.
- Retry only structured implementation transport failures (currently Pi `provider_transport_failure`), twice per invocation with cancellable 1s/2s delays and fresh sessions after durable-boundary rechecks; never infer authority from text or telemetry ([recovery](docs/plan-format.md#slice-lifecycle)).
- Telemetry is best-effort, never lifecycle/recovery authority: plan metrics use only `agent_metrics`, while repository batch `agent-events.jsonl` must never enter plan events or batch state ([telemetry contract](docs/plan-format.md#events)).
- Prompt capture is best-effort and never lifecycle or recovery evidence; it adds only `prompt_hash`/`prompt_template` to telemetry, and `tao report` never includes prompts.
- Insights collection stays deterministic, cancellable, sanitized, best-effort, and read-only; canonical-Tao-only review treats evidence as untrusted and environment checks as passive ([insights workflow](docs/usage-guide.md#tao-insights-review-focus--review-tao-wide-experience-evidence)).
- `tao insights --scorecard` is a read-only projection derived from plan summaries and events with an injected clock. Planner treatment comes from an explicit low-confidence normalization table over agent-written `plan_created.agent` labels, with ambiguous labels excluded by default. Rates use matured plans only and active plans are censored; infrastructure and quality reliability classifications are never netted. Reasoning effort is counted from sessions with `agent_metrics.reasoning_effort`; the scorecard has no prompt row, and `prompt_hash` on `agent_metrics` is the hook for future work. The digest output and existing fixtures are unchanged.
- Pi is the default built-in agent runtime; Claude Code (`TAO_AGENT=claude`) is also supported across prompt install, doctor, and run. Only `pi` and `claude` are valid selectors. Pi uses a fresh `pi --mode rpc` session per Tao operation; Claude uses fresh non-interactive sessions, stdin prompts, and stream JSON logs. `--dangerously-skip-permissions` is a compatibility no-op for Pi. Agent transcript sidecars are not currently written.
- Agent budgets are one `TAO_BUDGET_<SCOPE>_<METRIC>_WARN`/`_STOP` scheme loaded by the runtime env table into the single `EnvDefaults.Budget` field (`plan.AgentBudget`) and read only through `EnvSnapshot.Budget()`. Only the two slice `OUTPUT_TOKENS`/`COST` `_STOP` caps are registered and enforced; a `STOP` below its `WARN` is rejected on consumption via `Require`, never at load, and a nil `STOP` is disabled while an explicit `0` is a hard cap. The former `TAO_BUDGET_<SCOPE>_<METRIC>` and `TAO_MAX_SLICE_*` names are deprecated aliases for one release: they yield to a set canonical key and are hidden from `tao status` and the Settings tab unless set.
- `Session.Timeout` bounds run-path sessions, not interactive planning; note promotion must validate a normal plan and share the run path without bypassing safeguards ([run workflow](docs/usage-guide.md#tao-run-and-tao-run--execute-slices)).
- Approval requires a centrally validated exact-diff proposal; invalid proposals downgrade to `comment`, and non-approvals clear stale proposals ([review evidence](docs/plan-format.md#state-lifecycle)). Use live merge-base when computable, otherwise recorded creation base; severity guidance never weakens gates or grants retries ([review workflow](docs/usage-guide.md#tao-run-and-tao-run--execute-slices)).
- Rework preserves the same plan/branch and ordinary non-forced gates; consume recovery flags once via `run.Request.ForNextRound` ([rework](docs/usage-guide.md#decide-between-automatic-and-manual-rework), [escalation](docs/usage-guide.md#escalate-late-automatic-rework), [PR authority](docs/usage-guide.md#follow-up-on-pull-request-threads)). Persisted stops require explicit restart, while new location recurrence is advisory only ([stop evidence](docs/plan-format.md#events)).
- Tao alone mutates Git after durable intent and exact parent/message checks; preserve approved-proposal reuse, no title fallback, exact-head approval/verification, evidence-before-cleanup, idempotent settlement, and distinct single/batch flags ([intent](docs/plan-format.md#state-lifecycle), [single merge](docs/usage-guide.md#tao-merge--integrate-an-approved-plan-without-a-pr), [batch rules](docs/usage-guide.md#tao-merge---all--atomically-integrate-the-approved-set)). Batch progress remains display-only and nil-safe through `BatchProgressStore`, `Service.Progress`, and `BatchCoordinatorSeams.Progress` ([logs](docs/usage-guide.md#live-progress-and-batch-logs)).
- Direct-run gating must use the plan-recorded `state.repo.root`; unhealthy repositories remain visible in CLI repository views but are not runnable.
- Cross-process per-plan locks guard concurrent direct drivers. Legacy `queue.json` and `queue.jsonl` files under Tao data home are ignored and must not be deleted or migrated.

## Dependencies
- This module has zero third-party dependencies and must stay that way. Adding any third-party dependency (a `require` for a module other than `github.com/iamseth/tao`) requires explicit owner approval before it lands.
- CI enforces this: `make verify-no-deps` fails when `go list -m all` reports more than the main module, and the check runs in `.github/workflows/ci.yml`. Run `make verify-no-deps` locally before opening a pull request.

## Editing Guidance
- In event tests, assert on the event(s) the test owns by finding or requiring the specific type and checking its fields; do not assert total event-slice length or positional indices unless the test explicitly verifies the ordered sequence.
- Prefer focused package tests for changed code; use `make test` when changes cross packages or core behavior. Slices that change source or test code must also include `golangci-lint run --allow-parallel-runners ./<package>/...`, this repository's package-scoped lint form, for each touched package. Slices changing insights or other rendered output (including events, counters, or fields it includes) own the matching golden fixtures under `internal/cli/testdata`: list affected fixtures in `expected_files`, update them with `make update-golden`, and run each comparing test with no narrower filter, retaining whole-package verification for shared-seam work. Command, subcommand, and flag descriptions in `internal/cli` are rendered output: any slice that edits one must also own `internal/cli/testdata/zsh_completion.golden`, and plans must freeze only named fixtures (such as `internal/cli/testdata/insights`) rather than the whole `internal/cli/testdata` directory.
- Do not update local plan artifacts unless the task is specifically about Tao plan state or prompt behavior.
- When generating reusable planning prompts for `/tao-plan` or fresh agent planning sessions, save drafts with `tao draft-prompt <name>` (or another local-only path) so they remain local-only and are easy to pass to Pi or Claude.
- Keep prompt changes narrow because they directly shape future agent behavior.

## Repo-Local Agent Commands
- `tao steal fetch` is the only network operation for scouting; it uses a protocol allowlist, `--depth 1`, `--no-checkout` then checkout, symlink stripping, and a 200 MiB cap into `<data-home>/steal`; `prompts/steal.md` must never contain clone flags, and tests must never reach the network.
- Keep `/tao-pr` reviewer-facing title, body, category-label, and assignment conventions synchronized with the automated pull-request path unless an intentional divergence is documented.
- `prompts/run.md` implements exactly one pending slice and asks that same active agent for the structured commit proposal, then delegates validation, trusted trailers, intent, staging, recovery, and completion to `tao slice-complete`; it must not ask the agent to commit automatic slice work or start a nested message session. It delegates authoritative gates to Tao without a duplicate mandatory gate sequence/results file, authorizes minimal pre-intent in-session repair of declared-gate failures confined to the run packet's Plan-Owned Files and passes `--gate-command` plus repeatable `--failing-path` evidence to `tao slice-blocked` when blocking on a file-specific verification failure.
- `prompts/slice.md` allocates plan artifacts with `tao init --slug <short-slug> --json` and must not edit application files.
- `prompts/commit.md` is standalone/manual only and is a wrapper around `tao commit --context` plus `--proposal-file` (or explicit `--message`); Tao owns filtering, validation, staging, and Git. It is commit-only by default; only explicit `--push` authorizes Tao to publish the exact newly created SHA without force to the current branch's configured upstream. Pi and Claude wrappers forward that flag to context and finalization, never run Git directly, and never create an upstream or push on a no-op. Push failure preserves the local commit and must surface its SHA, destination, and manual non-force recovery guidance without retrying commit or publication. Automatic run or merge completion must not fall back to it.
- For the Pi agent, the `/tao-commit` command is hosted by the `extensions/pi` TypeScript extension (symlinked to `~/.pi/agent/extensions/tao` by `install-prompts`); see [`extensions/pi/README.md`](extensions/pi/README.md) for its build, test, and deploy details.
- The same Pi extension hosts `/tao-compose-reply` and its Ctrl+G external-editor override; see [`extensions/pi/README.md`](extensions/pi/README.md) for behavior, fallback, opt-out, and compatibility details.
- If committing manually, still exclude Tao data-home contents, workspace-local `.tao/`, and other local-only artifacts.
